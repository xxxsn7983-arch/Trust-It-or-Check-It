# Trust It or Check It

### 基于多模态 LLM 的儿童 Agent 游戏

> 面向儿童与 AI 协同学习场景，将大模型交互、多 Agent 协同和知识增强融入 Unity 游戏任务。

## 项目简介

**Trust It or Check It** 是一款面向 8–10 岁儿童的游戏化 Agent 系统原型，以神奇生物探索为主题，组织知识学习、初步判断、AI 对话、证据验证与情境应用等递进式任务。

本项目作为 AI 夏令营申请的项目展示，重点呈现如何将 AI 能力转化为完整的交互产品：通过有限状态机（FSM）管理任务与对话流程，结合 LangChain 多 Agent 协同、RAG 知识增强与多模态内容生成，并完成 Unity 前端与 FastAPI 后端的系统集成。

项目的核心是游戏任务与智能体协作的整体设计。partner-like、tool-like 和 dual-state 是不同的交互条件，用于探索不同任务阶段下的对话方式、知识来源与回复约束。

## 项目目标

- 将自然语言对话与游戏任务结合，使 Agent 参与探索、提示、反馈和任务推进。
- 通过 FSM 统一管理阶段、事件与交互边界，保持生成内容与游戏进度一致。
- 通过多个专职 Agent 支持对话、知识卡牌与个性化角色生成。
- 根据任务需要选择结构化知识、RAG 增强生成或直接 LLM 生成路径。
- 打通 Unity 与 Python 服务之间的数据传输、状态同步和内容展示流程。

## 游戏任务流程

| 阶段 | 玩家操作 | 系统支持 |
| --- | --- | --- |
| 知识激活 | 了解生物背景，形成初步判断 | 背景信息、任务提示与知识内容 |
| 反思触发 | 与 Agent 对话，对观点作出回应 | 按阶段组织回复与反思选项 |
| 证据修正 | 寻找线索、解释理由、验证判断 | 知识检索、证据评价与纠正反馈 |
| 情境应用 | 在后续情境中使用所学知识 | 任务推进、总结与游戏反馈 |

在特定探究环节，系统会按照任务设计引入可控错误观点，再通过证据与反馈完成修正。该机制由状态机管理，属于游戏任务的一部分。

## 系统设计

### FSM 驱动的动态交互

系统根据任务阶段与儿童输入调整 Agent 的回复策略、知识来源和内容范围。Unity 负责交互呈现与本地流程，后端负责对话状态及生成策略，两端通过 API 同步。

### 多 Agent 协同与多模态生成

整体项目采用统一任务状态下的协同设计，包含以下职责：

| Agent | 职责 |
| --- | --- |
| 对话 Agent | 自然语言交互、任务引导与反馈 |
| 卡牌生成 Agent | 将知识与对话内容组织为可展示的知识卡牌 |
| AI 形象生成 Agent | 根据用户选择与设定生成个性化角色内容 |

LangChain 用于整体项目中的生成与协同模块。文字、语音、角色图像与知识卡牌共同构成游戏交互内容；具体运行能力取决于相应模块、模型服务及 API 配置是否齐备。

### RAG 与知识约束

系统结合结构化生物知识库与检索增强生成，为任务相关对话提供知识支持。同时保留直接 LLM 生成路径，以适应不同阶段的交互需求。

### 三种交互条件

- **Partner-like**：强调陪伴与自然交流。
- **Tool-like**：强调知识、证据与任务支持。
- **Dual-state**：在统一流程中结合上述两种策略。

## 技术栈

| 层级 | 技术与职责 |
| --- | --- |
| 游戏前端 | Unity、C#，场景、角色、UI 与玩家交互 |

## 快速开始

### 启动对话后端

在仓库根目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/agent_project/requirements.txt
export PYTHONPATH="$PWD/backend"
```

在 macOS 默认 zsh 中安全输入模型密钥：

```zsh
read -s "QWEN_API_KEY?输入 Qwen API 密钥："
export QWEN_API_KEY
printf '\n'
```

然后启动默认服务：

```bash
python -m uvicorn agent_project.dual_state_agent.api_server:app \
  --host 127.0.0.1 --port 8030
```

访问 `http://127.0.0.1:8030/docs` 查看 API，访问 `/health` 检查服务状态。密钥通过环境变量传入，该入口不会自动加载 `.env`。未配置模型时，部分策略会返回固定回退内容。

### 打开 Unity 项目

1. 使用 Unity Hub 打开 `unity-client`。
2. 原项目版本为 **Unity 2022.3.42f1c1**，依赖配置见 `Packages`。
3. 默认对话服务地址为 `http://127.0.0.1:8030`；跨设备运行需修改地址。
4. 语音接口使用独立服务地址，例如 `http://localhost:5000/stt`；辅助服务中的 STT/TTS 包含占位实现，需要配置实际服务。

## 项目展示重点

- **交互产品实现**：从任务设计到 Unity 界面与后端服务的完整集成思路。
- **智能体工程设计**：将生成能力与状态机、知识约束和任务流程结合。
- **多模态协作设计**：将对话、角色和卡牌生成组织为统一的游戏体验。
- **实现取舍**：明确任务可控性、自然交互与知识可靠性之间的权衡。

## 当前状态与局限

本项目为研究与开发原型，不是生产服务。
